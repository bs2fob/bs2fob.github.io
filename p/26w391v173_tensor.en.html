Tensors and JSON

1. Physical tensors and deep learning tensors part ways

You hear the word tensor in two places: physics textbooks and AI news. The shared name makes them sound like one thing, but they do different jobs. A tensor in physics is an arrangement built so that it points to the same thing no matter which direction you look from. A tensor in deep learning is a table of numbers stacked in rows, columns, and layers. If one spreadsheet is two-dimensional, a stack of those sheets is a three-dimensional tensor.

A physical tensor is a multilinear quantity that follows specific rules under coordinate transformation. The transformation rule is part of its definition, and it has coordinate independence. Stress tensors and curvature tensors are examples, used in the formal domain where fixed axes, an assumed substance, and a demand for identical computation all hold — the formal-level transformation of <Cognitive Axioms 04_2>.

A deep learning tensor is a multidimensional array. No transformation rule is part of its definition, and it has no notion of a coordinate system. It shares only the name with the physical tensor; its purpose and mathematical structure are different. What LLMs use is the deep learning tensor.

2. What an LLM tensor is

In terms of my axis coordinate system, an LLM's tensor is a modified, simplified version built to hold the relational components between tokens — position, arrangement, layer, and so on.

Three of the four elements of an axis coordinate system survive intact in the LLM tensor. There are many axes, and coordinates are measured as real numbers. Units aren't dropped either. A unit isn't something agreed on and handed down from outside; it's built into the act of measurement called scaling. The scaling done in an LLM tensor is itself the act of setting units, so the units are already in place.

The only thing dropped is the axis names. Nothing inside an LLM records what each axis points to; the names live at the level of input, output, and interpretation. In this sense the LLM tensor is an axis coordinate system with only the names removed, and it is distinct from the physical tensor, whose definition includes a transformation rule.

3. JSON converges

Many data formats have been tried, but JSON — a plain-text delivery system that pairs axis names with coordinates in the simplest possible form — has settled in as today's general-purpose format for passing data around. JSON started from the goal of defining data and handing it over, and defining data calls for an axis coordinate system. JSON's two structures, objects and arrays, match the two ways an axis coordinate system points at things: by name and by order.

JSON carries no axis transformation formula, no assumed substance, no coordinate independence. The demand for definition, the match with the two ways of pointing, and the absence of axis transformation and substance: these three made JSON converge on the axis coordinate frame.

4. JSON's address

JSON becoming the general-purpose data format is an event on a separate track from the axis coordinate system. But the structure the format came with pointed at the axis coordinate frame from the start, and since that frame is the underlying structure of human cognitive computation, JSON's structure converges on it regardless of how it came to be widely used.

In the axis coordinate systems used in cognitive computation, the only thing in focus is the object's coordinates. The number of axes, the axis names, and the units are set up as preconditions for deriving them. For recording, preserving, and consulting things as data, JSON has been converging on the form of a container — a vehicle — that pairs coordinates with axis names and carries them. That is JSON's address as seen from the axis coordinate frame.
